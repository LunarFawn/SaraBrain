## The commitment

HamRoby's whole architectural argument is *no opaque sources, no
vendor lock-in, no third party in the inference loop, no third party
in the training loop either*. The L1/L2/L3 stack already gives this
for L1 and L2 — UD treebanks are open, content is user-owned. The
remaining open question was the synthesizer head (HamRobySum).

**The commitment this doc makes:** HamRobySum, like everything else,
is trained from open data + the user's own substrate. **No frontier
model is required to build, retrain, or extend any HamRoby
component.** Anyone with a GPU and the open inputs below can clone
the recipe end-to-end.

This explicitly forecloses v028's Path 2 (frontier-distilled
HamRobySum) as the canonical path. Path 2 remains *available* as a
quality polish for users who want it and are willing to pay the API
cost — but the canonical, supported, advertised loop is Path 1.

## Open inputs anyone needs

- **UD treebanks** — universaldependencies.org, CC-licensed, ~MBs
- **PyTorch** — open-source
- **spaCy** + `en_core_web_sm` — open-source, small download
- **Python 3.12** — open-source
- A GPU (3070-class is enough; CPU works for inference)
- The user's own `brain.db` — their data, their facts, never shared

That's the entire dependency list. No API keys. No accounts. No
"generated by" attribution to any third party.

## How HamRobySum learns without a frontier teacher

The labeler IS the teacher. `synth_data.py` already emits
`(edges → prose)` pairs from any `brain.db` using the post-v032
template renderer. The student learns:

- Which edges to combine and in what order (templates render
  edge-by-edge; the student sees the whole cluster)
- Which redundant edges to drop
- Which sentence shapes are most natural for which edge types

L2-en handles function-word grammar underneath. The student inherits
`a` / `an` / `the` / agreement from L2 and only has to learn
substrate-stitching.

What the student *can't* do that a frontier-distilled student could:

- Coin novel paraphrases the templates never showed (e.g. parenthetical
  construction, rich subordination)
- Use varied register / stylized prose

For HamRoby — designed to surface substrate facts honestly, not
produce stylized prose — those losses are mostly fine.

## Step 4 sub-slices (what's missing)

This doc enumerates Step 4 as a sequence of small, individually
shippable slices. Each is its own commit + plan doc.

### 4a — `vocab_synth.py`

Extends `vocab_en` with structural delimiters used in the synth-head's
prompt format:

- `<facts>`, `<prose>`, `</prose>` — top-level frame markers
- `<subj>`, `<pred>`, `<obj>` — per-edge field markers
- `<edge_sep>` — between edges in a cluster
- `<refuted>` — flag for refuted edges
- Possibly `<topic>` for topic-hinted clusters

~10-15 new tokens. Same append-above-existing-IDs pattern as
`vocab_en.py`. New `VOCAB_SIZE_SYNTH` ≈ 190.

### 4b — Serializer in `synth_data.py`

Converts each `SynthExample` (edges + prose) into a flat token stream:

```
<facts>
  <subj> inertia in rna <pred> is <obj> tendency to maintain current state
  <subj> ribosome <pred> part_of <obj> cell
<prose>
Inertia in rna is a tendency to maintain current state. Ribosome is part of cell.
</prose>
```

Substrate labels tokenize as a sequence of word tokens (whitespace
split + lowercase). For tokens not in the vocabulary, fall back to
character bytes — keeps the model from inventing identifiers but
allows OOV substrate content to round-trip.

Output: a JSONL file where each line is the input/target token-id
sequence ready for next-token training.

### 4c — `train_synth.py`

Mirrors `train_l2.py`. Loads `(L1, L2-en)`, projects into a
synth-vocab model, freezes L1 + L2 transformer blocks, trains:

- The new delimiter token embeddings
- The LM head (weight-tied to embeddings, so trains automatically)
- Optionally the top transformer block(s) — escalate if frozen
  setting under-fits

Trains on the JSONL from 4b. Standard cross-entropy next-token loss.
Dev split: hold out 10% of clusters from each brain.

### 4d — `inference_synth.py`

Adapter analogous to `inference_l2.py`. Takes an edge cluster, formats
the `<facts>...<prose>` prefix, decodes to `</prose>`, returns the
prose between markers.

Falls back to the v032 template renderer when:
- The synth checkpoint isn't available
- The prefix exceeds the model's `max_seq`
- Decoding hits `</prose>` immediately (degenerate case)

### 4e — Chat REPL integration

`chat.py` gains a `--use-hamrobysum` flag (and a matching
`--hamrobysum-ckpt`). When set, the synthesis stage calls
`inference_synth` instead of `synthesizer.render_edges`. The template
path stays as the default fallback.

### 4f — Side-by-side eval script

A tiny script that takes a list of substrate questions, runs each
through both the template path and the HamRobySum path, prints both
outputs side by side. No accuracy autograder — the user judges
naturalness vs. grounding by eye, since "natural prose" is exactly
the kind of thing where automated metrics mislead.

## What this means for the project's pitch

After Step 4 lands, HamRoby's pitch becomes:

> A grammar transformer + per-language function-word adapter +
> substrate-aware synthesizer. ~125M params total. Runs on a 3070.
> Trained from scratch on Universal Dependencies + your own
> brain.db. Zero API. Zero accounts. Zero opaque dependencies.
> Anyone can rebuild the whole stack from this repo.

That's the architecture v028 promised. Step 4 is what closes the
loop. Path 2 (frontier distillation) becomes a footnote: an optional
quality polish for users who specifically want it and are willing to
trade reproducibility for a bit more phrasing variety.
